# Coordinated workspace finish design (#374)

## Boundary and selection
`aw finish [target] [--dry-run] [--json] [--force] [--keep-branches] [--no-hook-input]` assesses one configured parent and optionally hands an accepted plan to remove. It never pushes, merges or deletes remote branches. `--force` authorizes discard and ordinary remove confirmation, not completion. No noninteractive manual-completion override or unsafe remove bypass. A preview may be blocked while its assessment succeeds. Evidence concerns an inspected tip and a current **named** integration target, not historical creation intent or content parity after reverts.

Resolve contextual registered parent/child via Git registration and physical path-component ancestry; reject ambiguous/detached/stale registrations, main/standalone targets and escapes. In main, omitted human TTY target uses single-select; non-TTY/JSON requires explicit target. Explicit path must identify exactly one registered parent; branch/fuzzy matches must be unique even among sibling worktrees. Inventory every configured child at its configured location beneath that parent regardless of branch. Absent location is a reported nonparticipant; present but unregistered, duplicate, inaccessible, missing canonical clone or unplanned descendant is a blocker. Compare repository+worktree identities to the closed exact-path remove plan; require no extra/missing worktree or branch actions, no no-op/branch-only plan.

Resolve existing path components with platform-native realpath, Git common-dir and `git worktree list --porcelain -z` registrations; compare components using filesystem-appropriate case/volume rules (including Windows drive/UNC), never textual prefixes. Recheck containment/registration at both gates. Missing paths cannot be asserted physically contained; changed symlink target invalidates. Privileged external actors can still race.

## Evidence and decision
For every participant keep an internal immutable snapshot of repository key, physical checkout/common-dir, branch/ref and full HEAD OID, staged/unstaged/untracked state, upstream ref/OID/ahead/behind or absent/unknown, configured base logical branch/source, remote identity/ref/OID or omitted/unknown, PR provenance, reason codes. Configuration precedence is repository > workspace > omitted. Invocation-only `create --base`/`--repo-base` is not historical policy. **Omitted base cannot silently become default**. An interactive operator may name a repository-specific target (remote identity and full base ref) for each omitted-base repository *before* assessment, recorded as `operator-selected` without changing config or claiming creation provenance. Without a named target integration stays unknown; manual completion judgment requires a named target. No target selection or manual judgment in JSON/non-TTY v1. Target/policy change invalidates consent.

Use an invocation-owned private temporary bare Git repository per source repo, created with platform temp APIs and restrictive permissions, removed in `finally` (including catchable signals/errors). `git init --bare`; fetch explicit base/upstream refspecs from the effective remote URL into temp refs, no prune/tags/source checkout writes. Import inspected local HEAD by exact OID from its Git common-dir into temp, without changing managed refs; a Git version/transport refusing unadvertised OID fetch yields unknown, never a fabricated object. If the object cannot be obtained, unknown. Account for Git URL rewrites/credential helpers without logging argv, environment, URL or stderr. Do not use source alternates, source `git fetch`, or assume separate object databases are shared. On Windows close Git handles before temp cleanup; no hardcoded `/tmp`. Fresh refresh at initial assessment, locked pre-handoff and post-hook gate; never use stale remote-tracking refs or silently accept remote advance. Preview status checks disable optional locks/index refresh (`git --no-optional-locks status --porcelain=v1 -z --untracked-files=all` with `GIT_OPTIONAL_LOCKS=0`); test managed index bytes, refs/config and worktree filesystem unchanged. If even a read can mutate them, isolate or mark evidence unavailable rather than presenting a side-effect-free preview.

Automatic Git proof is `merge-base --is-ancestor <HEAD> <fresh base OID>` within a complete isolated object graph. Detect and disable source/temp replace refs and grafts; shallow/promisor/incomplete graphs and missing objects make ancestry unknown, not a negative. Exit 1 (not ancestor), an ahead count, an open PR, or no PR **does not prove non-integration**: squash/rebase/cherry-pick may have landed. `not-finished` is reserved for a separately established positive policy fact; v1 does not infer it from negative searches. A failed fetch is unknown even when cached refs suggest integration.

GitHub proof is available only with authenticated, unambiguous GitHub repository IDs and exhaustive paginated closed/merged results. A unique merged PR requires exact head repository ID/branch, base repository ID/ref, mergedAt, merge commit reachable from fetched base, **and authenticated historical provenance binding the inspected local HEAD to the PR head at merge time**. Current `headRefOid`, current branch tip, commit association, or membership in PR commit list alone does not establish this. If API evidence cannot establish merge-time head (moved/deleted/reused branches, fork or later edits), squash/rebase integration stays unknown for manual judgment. Do not infer head from a squash/rebase merge commit parent. Pagination truncation, multiple/conflicting candidates, auth/forge/API failure or missing OIDs are unknown. A proven PR reports only safe number/URL and caveats that later revert is not detected. This intentionally limits automatic proof rather than promising unavailable provenance.

Dirty/untracked and absent/ahead upstream independently require discard consent even when integration is proven. Unavailable upstream is unknown, never zero. Aggregate invalid topology/local identity/plan => blocked; any separately proven not-finished policy fact => blocked; missing completion evidence => unknown; else ready. Human TTY may group unknown judgments by repo+named target+reason and then separately consent to discard; judgment records `manually-confirmed`, never `proven`. Hard blockers cannot be waived. A repeated network failure retains manual judgment only with identical named target, local identity and failure class; warn that remote freshness cannot be proved while offline. Successful contradictory refresh invalidates.

## Typed remove boundary and lock
Factor configured remove into `planConfiguredRemoval(selection, options): RemovePlan` (ordered worktree/branch action identities, hook targets/previews and policy) and `executeConfiguredRemoval(plan, options, internalFinishGuard?): RemoveResult` (the **only** destructive executor). Define typed immutable plans/results with operation, hook and partial-failure status; finish calls them in process, never shells out or parses CLI text. Internal guard receives accepted snapshot/plan and returns structured validation, not a public flag. Ordinary remove uses the same planner/executor without finish guard. Executor refreshes descendant closure after successful pre-remove hooks and checks accepted action/hook-target identities before the first destructive operation; it never appends a new target to a finish plan. Preserve ordinary remove's confirmations, dirty checks, hook order, branch defaults and partial failures.

Cross-process coordination uses one platform-atomic lock directory per canonical configured workspace root and one per touched Git common-dir in a configured local lock root, with each key a digest of that individual canonical identity; acquire root first, then individual common-dir locks in bytewise stable path order. Subset and full-workspace operations therefore contend on the same root rather than deriving incompatible aggregate keys. Store owner PID, start identity and random nonce with heartbeat; acquisition waits up to a bounded timeout and only recovers a stale lease after checking owner death and nonce under an atomic rename, never age alone. On filesystems where atomic directory creation/rename or owner liveness cannot be established, fail closed rather than stealing a lock. Every cooperating mutator of these worktrees participates: finish handoff, configured remove, prune and create paths adding/removing a contained worktree. Acquire before final pre-handoff snapshot; hold across remove confirmation, pre-hooks, descendant refresh, guard, destructive operations, post-hooks and finalization; release in `finally` only if nonce still matches. Initial assessment/preview runs outside lock and is always rechecked after acquisition. No nested second acquisition inside handed-off executor. Ordinary remove gains serialization but no finish-evidence policy. External Git/filesystem actors and remote updates do not honor lock; final validation narrows but cannot eliminate check-to-delete race. Do not claim atomicity.

After confirmation and lock acquisition re-read configuration bytes/policy, registration/physical identity, HEAD/dirty/upstream, base/PR observations and exact plan. Then remove's normal confirmation and hooks run. After successful pre-hooks and remove's descendant refresh, finish guard repeats reads and compares accepted snapshot/plan *before* detach/worktree/branch mutation. Changed hook targets, config, remote identity/OID, PR status/provenance or local state abort `FINISH_PLAN_INVALIDATED`, retaining hook outcomes. Failed local read aborts; repeated network failure only under unchanged explicit manual judgment. Hooks may already have side effects. After mutation begins retain remove's descendant-before-ancestor order, independent-operation continuation, branch policy, post-hooks and partial-failure behavior, without rollback promise.

## Safe projection and CLI contract
Single schemaVersion-1 finish envelope contains stable parent-first/child-key records/reasons, nullable facts, readiness, confirmations, nonparticipants, blockers/warnings and cleanupPlan/cleanupResult or null. **Never serialize remove's raw plan/result ledger directly.** Project typed actions/outcomes through an allowlist: configured repo key, operation kind, sanitized workspace-relative path, screened branch label, status, stable reason code and hook name/status. For untrusted path/branch/hook label emit stable opaque identifier and redacted label. Exclude hook stdout/stderr, exception messages, shell commands, raw URL/config/env, arbitrary Git error, PR body, commit message and hook source. Human and JSON use the same projection, including partial failures; test canaries across every input and error channel. Preserve attribution and partial-failure status without free-form strings.

Preview performs assessment and pure planning, no prompts/hooks/destruction; disposable network/object state is allowed. Invalid scope gives `cleanupPlan:null`. Completed preview even blocked/unknown or successful cleanup is `ok:true` exit 0; mutating ineligible/error/partial failure `ok:false` exit 1; missing/declined selection/confirmation exit 2. Codes: `FINISH_SELECTION_REQUIRED`, `FINISH_AMBIGUOUS_TARGET`, `FINISH_CONFIRMATION_REQUIRED`, `FINISH_DECLINED`, `FINISH_NOT_READY`, `FINISH_EVIDENCE_UNAVAILABLE`, `FINISH_PLAN_INVALIDATED`, `FINISH_REMOVE_FAILED`. Failure after target resolution carries safe full report in `error.details`; exactly one stdout document, no hook/prompt text in JSON.

## Approval boundary
`openspec validate --strict` is structural only. Independent semantic and architecture approval at this exact design HEAD precedes child code. Verify feasibility of historical PR head binding, cross-process lock participation, temp object transport and typed remove boundary. If impossible, revise/re-review rather than weaken checks. Compare correctness and maintenance cost with measured benefit before implementation.
