# Coordinated workspace finish design (#374)

## Value checkpoint and v1 boundary
`aw finish [target] [--dry-run] [--json] [--force] [--keep-branches] [--no-hook-input]` answers whether one configured coordinated workspace can be retired, then optionally hands it to existing remove. It does not merge, push, delete remote branches, reconstruct historical creation intent, or make remove atomic. The value is a conservative assessment and a guarded cleanup, not a new workspace-wide concurrency framework. Avoid a universal lock and create/prune/add/delete refactor, a wholesale split of the existing remove command, and test matrices for those unrelated changes. This is design-only; child implementations remain separate.

## Selection, assessment, preview
Resolve the contextual registered parent/child using Git registration and physical path-component ancestry. From main, an omitted human TTY target opens a single-select picker; selecting there is **selection only**, not preview or consent to delete. Explicit branch/fuzzy matches must be unique across sibling workspaces; an explicit path identifies exactly one registered parent. Non-TTY/JSON require an explicit target. Reject detached/stale/ambiguous registration, standalone/main targets, path escape and inaccessible identity. Inventory parent and every configured child at its configured location regardless of branch; absent children are reported nonparticipants. Present but unregistered, duplicated, inaccessible or missing canonical clone blocks cleanup. Match all worktree/branch/hook targets against the exact closed remove plan; never delete an unassessed descendant or unrelated branch.

After selection, `--dry-run` assesses and plans without cleanup prompts, hooks, detach, worktree/branch deletion, or incidental managed index/ref/config/worktree writes. The picker may prompt for selection, but **preview must not prompt for target policy, manual completion, discard or remove confirmation**. If a base is omitted, preview reports unknown with no silently selected default. Interactive target naming and grouped manual judgment belong only to execution, followed by reassessment. A blocked/unknown preview can succeed as a preview while explicitly saying cleanup is not authorized.

For each participant report exact HEAD, branch, dirty/untracked state, upstream OID/ahead/behind or unknown, effective configured base (repository > workspace > omitted), named remote/ref/OID, integration evidence and stable reasons. Current configured base is not historical creation base; invocation-only create overrides are not inferred. If omitted, an executing interactive operator can name a repository-specific remote and full base ref without changing config; non-TTY/JSON cannot do this in v1. Manual completion requires that named target.

## Fresh evidence without workspace mutation
Use `git fetch` of explicit base/upstream refs against the effective remote into an invocation-owned private bare repository (platform temp API, restrictive permissions, cleanup in `finally`). Import the inspected local HEAD object/history by fetching its exact OID from the local repository as a local Git source where supported; if that transport refuses an unadvertised OID or history is incomplete, ancestry is unknown. No source alternates, source fetch, prune, tags, managed remote-tracking ref updates or checkout mutation. Resolve Git remote configuration/URL rewrites normally, but suppress sensitive transport diagnostics from output. Fetch before assessment and again before handoff and the finish-specific post-hook gate; compare identities/OIDs. Preview status uses optional locks disabled and index-refresh suppression; test managed index bytes, config, refs and worktree unchanged. Network fetch and disposable temp files are permitted and must be described as metadata refresh, not a perfectly side-effect-free process. If a Git read cannot avoid managed writes, report evidence unavailable rather than claiming nonmutation.

Exact HEAD ancestry of the fresh named target OID in a complete graph proves integration; disable replace refs/grafts, and treat shallow/promisor/missing history as unknown. Negative ancestry, ahead counts, open/no PR and deleted branches are not proof of non-integration after squash/rebase/cherry-pick. Do not assign `not-finished` from these negatives. Later reverts are not detected.

Attempt `gh` only when authenticated GitHub repository/head/base identity and complete, paginated evidence can be verified. A merged PR with matching current head/branch and reachable merge commit is useful **correlation**, not automatic exact-HEAD proof of a squash/rebase merge: current `headRefOid`, commit list and merge commit parents do not establish the inspected HEAD at merge time. If a verifiable immutable merge-time binding is unavailable through the actual `gh`/GitHub response, classify unknown and offer grouped manual completion in interactive execution. Do not invent an endpoint or historical proof. Ambiguous candidates, auth/rate/pagination failure, fork/branch reuse and other forges remain unknown. Direct ancestry can still prove integration independently of PR correlation.

Dirty/untracked and absent/ahead upstream separately require discard consent. Unavailable upstream is unknown, not zero. Hard topology/identity/plan blockers cannot be manually waived. Group unknown completion judgments by repository, named target and reason; acceptance records `manually-confirmed`, never `proven`. `--force` covers discard and ordinary remove confirmation, never completion. JSON/non-TTY cannot manually confirm completion. Decline leaves worktrees/branches untouched.

## Minimal remove handoff and residual race
Reuse the existing configured remove plan and execution path, including descendant-before-ancestor ordering, confirmations, dirty checks, lifecycle hook order, branch retention and partial failures. Add only a narrow internal way to obtain/compare the intended operation and hook-target identities and an optional finish-only callback immediately after successful pre-remove hooks and remove's descendant refresh, **before the first destructive detach/worktree/branch action**. Do not extract a general pure planner/executor or redesign ordinary remove. Finish supplies its accepted identity/evidence snapshot; the callback re-reads local configuration, registration/physical paths, HEAD/branch/dirty/upstream and fresh base/PR evidence, then compares the exact closed plan. Also revalidate after interactive consent before handing off to remove. On mismatch or failed required local read, abort before mutation with structured invalidation and retain already-run hook outcomes. A repeated remote failure may retain only an unchanged explicitly manual judgment with the same target/local identity/failure class and a freshness warning; a successful contradictory refresh invalidates. After mutation starts, retain ordinary remove's partial-failure semantics and never promise rollback.

No new shared cross-command lock: add, delete, create, prune and ordinary remove remain unchanged. External Git/filesystem operations and concurrent Arashi invocations can change state between final gate and deletion, including after a successful gate; even repeated checks do not make this atomic. Document this residual race plainly, and never claim cross-process serialization or guaranteed prevention of all stale deletion. Hooks may already have side effects when the gate aborts.

## Output and approval
A schemaVersion-1 finish envelope reports stable parent-first/child-key ordering, nullable unavailable facts, readiness, confirmations and projected cleanup plan/result. Project only allowlisted operation/hook status, safe labels and stable reason codes; never serialize raw remove ledgers, hook output, Git/exception text, raw URL/config/environment, PR body or commit messages. One JSON stdout document; preview completion (including blocked/unknown) exits 0, missing/declined selection/consent exits 2, failed ineligible mutation/invalidation/partial removal exits 1. Preserve a safe report after target resolution.

`openspec validate --strict` checks structure, not feasibility. Obtain semantic and remove-architecture review at this signed exact HEAD before child code. Verify the actual `gh` evidence surface, private fetch and callback placement against child implementation; if infeasible, revise and re-review. The v1 benefit must remain proportionate to the small finish-specific integration surface.
