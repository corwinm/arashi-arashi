## Decisions

1. Use official authenticated HTTP orchestration snapshot/thread-detail/dispatch endpoints. Read only `server.getConfig` over ticket-authenticated Effect JSON RPC WebSocket for catalog and defaults. Do not recreate subscriptions, general client state, T3 Connect, or provider clients.
2. Require an already-installed official `t3` CLI at matching version. `t3 auth session issue --base-dir ... --ttl 5m --json` issues a bounded session, `revoke` removes only the owned session. Desktop authentication is private IPC/bootstrap, not a supported Arashi interface. No private SQLite or credential store access; the CLI owns auth persistence. No runtime download. The smoke uses a checksum-verified official release archive in a test-owned temporary directory.
3. Select `defaults.t3.baseDir` / `--t3-base-dir`, else `T3CODE_HOME`, else `~/.t3`. Read only `userdata/server-runtime.json`; reject non-loopback, credential-bearing, malformed endpoints. Do not port-scan or guess among profiles. Authenticated metadata, scopes, catalog, snapshot, exact version and protocol are verified before workspace mutation; discovery errors identify selection/restart remedies. Custom dev profiles must expose this runtime layout; remote environments are out of scope.
4. Config ownership: `defaults.t3.{provider,model,effort,baseDir,cli}`. Precedence per field: CLI > workspace > user `~/.arashi/config.json` > T3 project selection > T3 server selection > unambiguous catalog defaults. No model slug fallback. Provider routing uses instanceId; a driver name is accepted only if unambiguous. Effort maps to the catalog's `reasoningEffort` or `effort` descriptor. Resolve selection after moves against the exact project, before any T3 mutation, so project defaults are honored even with effort-only overrides. Reject relative CLI executable paths before workspace mutation. Validate option values. Report effective selection without prompt/auth data.
5. Coordinate conceptually with #387: same user file, namespace, per-field layering; T3 reads only its applicable section through an isolated resolver. No other workspace is edited and no generic user-default implementation is duplicated. #387 can later route this section through its general loader. Users explicitly copy bridge preferences into this namespace or use flags; Arashi never silently reads bridge config.
6. Exact canonical parent path is the project workspaceRoot; thread worktreePath is null and no worktree bootstrap is submitted. Dispatch follows all moves. UI mode stays `none`, exact-thread navigation is false/skipped. Manual selection in a client connected to the same environment is the supported outcome; revealing a desktop app would not prove exact-thread navigation.
7. Retain owner-only atomic receipts and exclusive lock in Git common dir. Version-1 bridge receipts fail closed, including previously definite failures, until manual reconciliation. Version-2 saves environment, project/thread/message IDs before each mutation and `submitting` before task POST. Preparation retries reconcile known IDs; uncertainty retries read the recorded message to confirm acceptance, never POST the task again. Missing/deleted/changed identifiers block recovery. Receipt/lock/auth cleanup errors preserve proven remote outcomes. Stale locks need explicit reconciliation/removal, never automatic stealing.

## Risks and boundaries

T3 is independently versioned; 0.0.43/protocol 1 is the explicit supported/tested range, not a promise about future releases. HTTP success proves orchestration acceptance, not provider completion. Local running environment only; selected data directory must belong to the repository host. macOS arm64 is the real smoke platform; simulated Windows ACL coverage and platform-shaped discovery tests do not constitute Windows/Linux/mobile end-to-end evidence. The normal adapter never opens UI or persists task text. Prompt text travels only in authenticated HTTP request bodies, not argv or temporary prompt files.
